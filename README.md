# Office heater

Local-network control of the Klarstein IR panel (Tuya / Smart Life) from the Mac Mini.
No cloud calls at runtime.

- **Sleep** → heater OFF immediately (synchronously, before Wi-Fi drops).
- **User wake** (display wake, not Power Nap / dark wake) → heater back ON, but only if *we* switched it off,
  you didn't switch it off yourself today, and (optionally) it's working hours.
- **Menu bar** (HeaterBar, native app): flame icon + `room → target` in the top bar. Left-click opens the
  panel (on/off switch, ±1 °C, Eco/Comfort/Boost presets, auto-off timer, automation status);
  right-click switches the heater on/off directly. Presets live in `config.toml` → `[presets]`.
  Prefer xbar? `./install.sh --xbar`.
- **Fail-safe**: the heater's own countdown timer is re-armed every 5 min by a watchdog while the Mac is
  alive, so if the Mac crashes or loses power the heater switches itself off within `safety_timer_hours`.
  The watchdog also turns it off after `idle_off_minutes` without keyboard/mouse input.

## Setup

```bash
./install.sh                      # venv + tinytuya, sleepwatcher, `heater` on PATH, xbar plugin
```

1. **Wizard (you run this; it asks for your Tuya IoT API key/secret).** In Claude Code, prefix with `!`:
   ```
   ! cd <this folder> && .venv/bin/python -m tinytuya wizard
   ```
   It writes `tinytuya.json`, `devices.json`, `snapshot.json` here. All are secrets and git-ignored.
   Re-pairing the heater in Smart Life changes the local key → rerun the wizard.
2. **Discover**: `heater discover` prints IP + protocol version (no secrets). Give that IP a
   **DHCP reservation** in your router and put it in `config.toml` → `[device] ip`.
3. **Map data points**: `heater map`, change one setting at a time on the panel, record results in
   `DPS.md` and `config.toml` → `[dps]`. Check whether the timer turns the heater *off* on expiry.
4. `./install.sh` again → loads the launchd agents (sleepwatcher + watchdog).
5. Optional: `./install.sh --mcp` and register the MCP server (command is printed).

## CLI

```
heater status [--json]     heater on [temp]     heater off
heater set 22              heater up | down     heater timer 2   (0 = cancel)
heater mode <value>        heater lock on|off   heater raw
heater state [--reset]     heater watchdog      heater hook sleep|display-wake
```

`heater off` (and switching it off on the panel/app, detected by the watchdog) counts as a **manual off**:
no auto-ON on wake until you turn it on again or the day changes.

## Files

| Path | What |
|---|---|
| `config.toml` | all tunables (temps, hours, wake behaviour, fail-safe) |
| `heaterctl/` | device wrapper, policy logic, CLI |
| `hooks/` | sleepwatcher scripts (sleep, display sleep, display wake) |
| `menubar/` | HeaterBar SwiftUI app (`build.sh` compiles it; install.sh copies it to ~/Applications) |
| `~/Library/LaunchAgents/com.officeheater.*.plist` | generated by install.sh |
| `~/Library/Application Support/heater/state.json` | auto-off reason, manual-off flag, cached IP |
| `~/Library/Logs/heater.log` | log (never contains keys) |

Tests (offline, fake device): `.venv/bin/python -m unittest discover -s tests -v`

## Notes / limits

- Heater Wi-Fi is 2.4 GHz only. If the mains rocker is off the device is unreachable; every command
  fails cleanly with "Heater not responding" and the menu bar shows `🔥 ?`.
- If the safety timer expires (Mac gone), the watchdog will later see "off" and treat it as a manual
  off, so it won't auto-restart. That's deliberate (conservative).
- The launchd agents point at this folder; if you move it, run `./uninstall.sh` first and `./install.sh` after.
- Later: an M5Stack Cardputer heartbeat watchdog on the LAN (off if the Mac is gone > N min).
